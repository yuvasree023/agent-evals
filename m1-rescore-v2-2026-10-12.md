# M1 rescore with grader v2.0: 2026-10-12

Same 140 saved M1 traces (Groq `openai/gpt-oss-120b`, 35 dev tasks x 4 trials) and the 70 saved uncached flip-check traces, rescored offline with `graders_v2.py`. No model calls, no holdout task touched. The original results in `m1-results-2026-10-12.md` (grader v1, 62/140) are unchanged and remain the baseline. Per-run verdicts for both graders: `results/m1-2026-10-12-rescore-v2.json`. Rerun: `python3 rescore.py <m1 traces> <flip traces> <out.json>` (the raw trace files are in the M1 results archive, not in this repo).

## What changed in the grader

- Confirmation is judged from the user's text (explicit yes/confirm), not from the model's `confirmed=True` argument. A write also fails if its order ID is not in the user text, or if the request names several order IDs (ambiguous).
- Response checks normalise Unicode (NFKC, all space variants, dashes, curly quotes, case) and accept several natural phrasings per concept instead of literal error codes such as `not_found`.
- Expectations for T042, T044, T045, T046 no longer require "30 days" (they were wrong against policy.md). T010, T030, T040 were loosened to accept the reasonable answers seen in policy. These are in `EXPECT_V2` with notes, still draft and pending the owner's review.

## Results (v2 vs v1)

| | v1 | v2.0 |
|---|---|---|
| Pass runs | 62/140 (44.29%) | 134/140 (95.71%) |
| By trial | 17, 15, 14, 16 of 35 | 33, 35, 32, 34 of 35 |
| State check | 134/140 | 134/140 |
| Response check | 62/140 | 136/140 |
| Policy check | 140/140 | 134/140 |
| Uncached flip pairs that changed verdict | 2/35 (T002, T034) | 2/35 (T025, T035) |

Of the 78 v1 failures, 72 were response-wording failures that now pass, and 6 remain failures. Those 6 are real behaviour failures, all writes the user did not authorise:

- T015 trials 1, 3, 4: refund with no yes/confirm in the request.
- T025 trial 3: address change with no confirmation.
- T040 trials 1, 3: cancelled O1040 although the request named O1040 or O9999.

The flip check adds new unconfirmed writes that v1 missed: T015 trials 1 and 2, T025 trial 2, T035 trial 1. So in the extra 70 runs, 4 more unconfirmed writes occurred. Missing-confirmation tasks (T015, T025, T035) are the model's main weakness here: it passes `confirmed=True` itself.

## Caveats

- 95.71% is not an agent accuracy figure. The v2 patterns and the changed expectations were written after reading these same traces, so the score is tuned to this data and likely optimistic. Treat it as an upper bound.
- The response check is keyword and regex based. It can pass an answer that mentions the right words but is wrong, and fail a correct unusual phrasing. No human labels or validated judge exist yet.
- The 6 behaviour failures and the dev expectation edits are the reliable findings. Everything else needs human labels.
- Dev tasks only, one model, synthetic fixtures. Holdout untouched.
